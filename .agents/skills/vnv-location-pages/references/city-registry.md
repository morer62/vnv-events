# Approved 62-city registry

The repository documentation does not currently contain one authoritative explicit 62-city list. Public service-area material contains a larger historical mixture of cities, municipalities and neighborhoods, so never truncate it arbitrarily.

## Resolution procedure

1. Inspect the most recent completed production location-page cycle and extract its ordered city, county, slug and route set.
2. Compare it with current Growth Hub priorities, unified CMS location pages, the public service-area page and sitemap.
3. Normalize names without merging distinct approved markets.
4. Remove neighborhoods or aliases only when a prior approved cycle proves they are outside the 62-city registry.
5. If the result is not exactly 62, has duplicates or conflicts with current priorities, present the discrepancy to Jonathan for an explicit decision.
6. Never select the first 62 entries from a larger list or invent replacement cities.

## Frozen fields and batches

Retain ordinal position, city/market, county (`Miami-Dade`, `Broward`, `Palm Beach`), normalized slug, planned route, existing-route status and batch.

After approval freeze the order:

- Part 1: 1-15
- Part 2: 16-30
- Part 3: 31-45
- Part 4: 46-62

Do not silently change the registry between parts.
